# Comparison with google/protobuf

The benchmarks here measure the library against [google/protobuf](https://github.com/protocolbuffers/protobuf/tree/main/php),
the official implementation, in both of its forms: the runtime written in PHP and the C extension. The results are in
the "Performance" section of the README of the repository.

```shell
make bench-compare
```

It prints the results of each run and then the tables of the README, which it also writes to `var/comparison/report.md`.
`ARGS` goes to phpbench: `make bench-compare ARGS='--filter=Nested'` runs one benchmark, though the tables need them
all.

## What is measured

Each `*Comparison.php` is one message of `benchmarks/Fixture`, the same the benchmarks of `make bench` use, and
`comparison.proto` declares the same messages for google/protobuf. For both libraries the message is

- encoded,
- decoded,
- decoded and read: every value of the decoded message is read.

The last one is there because decoding alone favors the extension: it keeps the decoded message in its own memory and
makes a PHP value of a field only when it is read, while this library and the PHP runtime of google/protobuf make them
all at once.

Both libraries get the same work. The bytes to decode are those this library writes, the message google/protobuf
encodes is decoded from them, and before the measurement the setup checks that reading every value gives the same
number for the message, for what this library reads of the bytes google/protobuf writes, and for the message of
google/protobuf.

## How it runs

google/protobuf is not a dependency of the library, so nothing of it is installed with the project. `make bench-compare`
makes what it needs on first use:

- the image of the `comparison` service of `compose.yaml`, built with `Dockerfile`: the php image of the project
  without Xdebug, which slows the code down even when it is off, and with the extension of google/protobuf installed
  but not loaded, and the settings of the JIT written but not read;
- the PHP runtime of google/protobuf, installed by Composer into `var/tools/google-protobuf`;
- the classes of `comparison.proto`, generated by `generate.sh` with protoc into the same directory.

The release of google/protobuf is the one that goes with protoc pinned in `tests/tools/protobuf.sh`: `5.36.2` for
protoc `36.2`.

phpbench then runs with `phpbench.json`: OPcache on, assertions off, every iteration in a process of its own.

1. Without the extension: this library and the PHP runtime of google/protobuf.
2. With the extension loaded, by `PHP_INI_SCAN_DIR`: the subjects of google/protobuf only. The generated classes are
   the same, the extension takes the place of the classes of the runtime.

Both runs are then repeated with the tracing JIT, turned on by `PHP_INI_SCAN_DIR` too: `opcache.jit=tracing` with a
buffer of 128 MB.

`report.php` makes a table of the two results without the JIT and one of the two with it. A time in them is the median
of the iterations.

## CI

The `comparison` job of the `check` workflow runs `make bench-compare` and leaves the tables in the summary of the run.
The times of a shared runner are noisy, so the job fails only when the comparison itself does, and its tables are to be
read by how the libraries relate, not by the times.

After a change that moves the numbers, run `make bench-compare` on a quiet machine and put the tables into the README of
the repository.
